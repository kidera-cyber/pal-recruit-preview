## 3. 旧 ABOUT URL（`/renewal/about/`）の扱い

### GitHub Pages の制約

GitHub Pages（プロジェクトページ）では、**サーバー側の HTTP 301 リダイレクトを設定できません。**
`_redirects`（Netlify）や `.htaccess`（Apache）も効きません。

### 取りうる方法

| 方法 | 内容 | SEO | アクセシビリティ |
|---|---|---|---|
| **⒜ 案内ページ（推奨・プレビュー作成済み）** | 旧URLを「移動しました」ページに置き換え、コーポレートと採用内の両方へ手動で進んでもらう | 301ではないため**リンク評価は引き継がれません**。`noindex` を付けてインデックスから外すのが無難 | 利用者が自分で選べるので最も安全 |
| ⒝ ⒜＋`<meta http-equiv="refresh">` | 一定秒数後に自動遷移 | 301ではない。Googleは遅延のあるリフレッシュを推奨していません | **自動遷移はスクリーンリーダー利用者や操作中の利用者に不利。**使うなら5秒以上＋停止手段が必要 |
| ⒞ JavaScript での `location.replace` | 即時遷移 | 同上。JSオフでは動かない | ⒝と同じ問題 |
| ⒟ 独自ドメイン＋サーバー側301 | 本番ドメイン確定後にホスティングを選べば可能 | **唯一、正しく評価を引き継げる** | 問題なし |

**現時点では ⒜（案内ページ・noindex）を推奨します。** 本番ドメインへ移る際に ⒟ へ切り替える、という二段構えです。
`renewal/culture/` で同じ事情から meta refresh を使った前例がありますが、そのときも301ではない旨を記録しています。

**旧URLは削除していません。**承認後に案内ページへ切り替える手順です。
