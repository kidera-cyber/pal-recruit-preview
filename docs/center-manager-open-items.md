## 1. 現行JOBSのセンター長情報の出どころ

`renewal/jobs/index.html` の `#job-bpo` と `renewal/jobs/center-manager/index.html` に
掲載している条件は、**すべて `original/index.html`（リニューアル前のモックアップ）からの引き写し**で、
拠点ごとに確認された正式条件ではない。

| 項目 | 現在の記載 | 分類 |
|---|---|---|
| あるべき姿 | 現場が自律的に回り、成果を生み続ける状態をつくる | A：共通・確認済み（WORK／FAQとも一致） |
| 雇用形態 | 正社員（試用期間3ヶ月） | **E：拠点共通かどうか未確認** |
| 対象 | 現場マネジメント・オペレーション改善・数値管理の経験者歓迎／未経験・新卒可 | A：共通（FAQとも一致） |
| 想定年収 | 350万〜700万円 | **D／E：仮情報。拠点別の正式条件ではない** |
| 勤務地 | 担当拠点（大阪・東京ほか） | **B：拠点ごとに異なる。「ほか」の中身が不明** |
| 勤務時間 | 実働8時間（拠点によりシフト制） | **B：拠点ごとに異なると明記されている** |
| 休日休暇 | 完全週休2日（土日祝）、年末年始、年次有給、慶弔、育児・介護休業 | **B／E：シフト制の拠点と矛盾する可能性** |
| 福利厚生 | 各種社会保険完備、交通費支給、研修制度、資格取得支援 ほか | A：全社共通とみられるが要確認 |
| 選考 | エントリー→カジュアル面談→面接（複数回）→最終面接→内定（Web面接可） | A：全職種共通（ENTRYページ記載） |
| 応募先 | `renewal/entry/` → **`contact-service/`（BtoB営業フォーム）** | **E：仮設定。未解決** |
| 募集状況 | NOW HIRING | **E：拠点単位の募集状況が不明** |
| JobPosting | 未実装（`docs/jobposting-ready.md` に雛形あり） | — |

### センター長とセンター長候補の違い

**リポジトリ内に、両者の担当範囲・責任・応募条件を分けた記述はない。**
現在の募集は「センター長／候補（現場運営）」としてひとつにまとめられている。
推測で分けることはできないため、共通紹介ページでは「社内で確認中」と明記し、
拠点別テンプレートには両者を分けた欄だけ用意している。（分類 C は現時点で空）

| 確認項目 | 内容 | 現状 |

## 3. 正式公開までの手順

1. 上の表を拠点ごとに埋める（顧客名・社内呼称を公開してよいかもあわせて確認）
2. `data/center-manager-jobs.json` の `positions` に1拠点1レコードで追加し、
   社内確認が済んだものだけ `"status": "confirmed"` にする
3. `python3 -I tools/build_center_manager.py` を実行
4. デモレコード（`DEMO-CM-01`〜`03`）を JSON から削除する
5. ビルド関数の `preview=False` で正式ページを生成する
   （LEVEL 01 → `renewal/jobs/`、LEVEL 02 → `renewal/jobs/center-manager/`、
     LEVEL 03 → `renewal/jobs/center-manager/<slug>/`）
6. `datePosted`（掲載開始日）を決める。JobPosting は `confirmed` の拠点にだけ出力する

### JobPosting を出す条件（`docs/jobposting-ready.md` と同じ）

- 掲載開始日が確定している
- 応募フローが確定している（現在 ENTRY は仮設定）
- 勤務地・給与・雇用形態がページ上の表示と一致している
- 募集していない拠点・確認中の拠点には出力しない
