Our Work

仕事を知る。

PALの仕事は、現場・システム・データ・設備をつなぎ、物流DXを現場で動く形にすること。
ひとつの職種だけでは完結しません。

How We Work

職種は違っても、
向き合っている課題は同じです。

GOAL 物流DXを、
現場で動く形にする
  • BPO / 現場運営現場を安定して回し、改善を積み重ねる
  • FDE課題を技術要件へ翻訳し、実装までつなぐ
  • システム / プロダクト現場で使われる仕組みを設計・開発する
  • 営業 / コンサル・DTS顧客の課題を整理し、現場の実行につなぐ
  • コーポレート各部署が仕事に集中できる環境を整える

STEP 01-04理解する

  1. 現場を見る
  2. 課題を理解する
  3. 業務を整理する
  4. 技術要件へ翻訳する

STEP 05-08実装・改善する

  1. 設計する
  2. 実装する
  3. 運用する
  4. 改善する

※ この流れ全体を一続きで担うのがFDE。他の職種は、それぞれの専門領域から関わります。

What makes it different

PALの仕事の特徴。

  • 01現場とデジタル、両方を見る

    現場を理解していなければ、データや技術は使われる形になりません。

  • 02設計だけで終わらず、実装まで関わる

    提案書で終わらず、実際に動く仕組みにするところまで担当します。

  • 03導入後の運用・改善まで見る

    運用そのものを請け負うから、使われ方を見て更新し続けられます。

  • 04複数の専門領域と連携する

    経営・現場・3PL・SIer。立場の違う相手と組んで進めます。

Careers

現場を起点に、8つのフィールド。

PALの事業は、現場（まわす）を土台に、つくる・つなぐが循環し、その結節点にFDEがいます。なかでもセンター長（現場運営）とFDEは、事業の起点となる中核職種です。新卒も、キャリアも。技術力より人物面を重視して迎えます。

※「関わる段階」は Design / Deploy / Operate / Evolve のどこに主に関わるかの目安です。実際の担当範囲はプロジェクトによって変わります。

FORWARD DEPLOYED ENGINEER

仕様書だけでは、現場は動かない。
だから、現場に入り込む。

一般的なFDEとは。顧客の業務課題と技術の間をつなぐエンジニアの職種。技術を実際に使える形へ落とし込むところまで関わります。

なぜ物流DXで必要か。現場にはデータ構造・帳票・権限・設備・レイアウトなど、現場ごとの制約があるためです。

PALでは何をするか。現場理解から始め、Design → Deploy → Operate → Evolve の4サイクルで、設計・実装・運用・改善までを分断させずに進めます。

※ FDEは物流コンサルティングやSIerを置き換える役割ではありません。それぞれの専門領域と連携しながら、現場で実際に使われる状態まで実装を進めます。
